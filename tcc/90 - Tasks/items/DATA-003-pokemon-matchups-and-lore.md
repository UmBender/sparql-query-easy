# Extend PokemonGen1 with per-Pokémon strengths and Pokédex lore links

## Objective

The user wants to explore Pokémon matchups (weaknesses and strengths) and lore
in which one Pokémon's Pokédex entry cites another. `DATA-002` already models
the type chart and each Pokémon's defensive side (`weakTo`, `fourTimesWeakTo`,
`resistantTo`, `immuneTo`). This task adds the offensive side and lore links
to the same `PokemonGen1` dataset. Skill: `tcc-backend`.

Expected examples once done:

- The types Charmander is strong against (Grass, Ice, Bug, Steel).
- Every Pokémon strong against Water types; every Pokémon weak to Pikachu's
  attacking types.
- Slowbro's Pokédex entries cite Shellder (biting its tail), and Shellder is
  therefore `mentionedInPokedexOf` Slowbro. Candidate links such as these are
  checked against references before they are added.
- All Pokémon whose Pokédex entries cite Pikachu, and the reverse.

## Decisions taken for this card (user request 2026-10-07)

- Same dataset and endpoint `PokemonGen1`, same generator
  `scripts/generate-pokemon-dataset.mjs`; regenerated bytes stay deterministic.
- **Strengths** are type-based, computed by the generator from each
  Pokémon's own type(s) and the existing chart: `strongAgainst` (types at least
  one of its types hits super effectively). Not a 151×151 Pokémon-vs-Pokémon
  table; Pokémon-to-Pokémon advantage is reachable by joining through types.
  A not-very-effective/no-effect offensive counterpart may be added if cheap
  and clearly labelled.
- **Lore:** Pokémon-to-Pokémon links where a Pokédex entry of one Pokémon
  (any game) mentions another species of the 151, e.g. `pokedexMentions` and
  the inverse `mentionedInPokedexOf`, each with an `rdfs:label`. A short
  paraphrased note per link or per Pokémon is allowed; no verbatim in-game
  flavor text (DATA-002 rule kept). Each link is listed in the generator's
  source table with the game whose entry supports it, so reviewers can check.
- Missing or uncertain lore is omitted rather than invented.

## Scope

1. Generator tables and output (`pokemon_gen1.ttl`) with the new properties,
   declarations and labels; the generator's count checks extended.
2. Oracle tests in `PokemonDatasetTest` for strengths and lore (including
   inverse links) and a route-level check if a new relation must surface in
   relationship/search routes.
3. Docs: API v1 / Current Contracts built-in dataset description and the
   DATA-002 limitations if they change.

## Exclusions

No changes to `futebol_completo.ttl`, to the frontend, to other generations,
or calls to live services at build/test time.

## Acceptance criteria

- [ ] Charmander `strongAgainst` exactly Grass, Ice, Bug, Steel; a dual type
      (e.g. Bulbasaur Grass/Poison) is the union of both types' strengths.
- [ ] Lore links exist in both directions, every endpoint is one of the 151,
      and at least a reviewed set of well-known cases is asserted by tests.
- [ ] `node scripts/generate-pokemon-dataset.mjs --check` passes.
- [ ] `ktlintCheck detekt test` passes; `installDist` smoke of `PokemonGen1`.
- [ ] `node scripts/check-project-docs.mjs` and `git diff --check` pass.
